4. MLS Sync Operations

The sync page is the most important operational screen on the site.

Action When to Use It Expected Result
Run Full Sync Initial load or after a major logic change Broad reprocessing of source data
Run Incremental Normal recurring update Faster source refresh since last checkpoint
Run Cleanup Stale or hidden listing troubleshooting Cleanup-only behavior
Stop Run Run started by mistake or must be paused Stops at the next safe boundary

Important Sync Note

Incremental sync also runs the current municipality cleanup logic. That means it can remove listings that were mistakenly imported into King from places like Kingston or Kingsville.

9. Showing Request Flow

  1. User opens the showing request form from a listing page.
  2. User enters name, email, phone, message, and SMS consent preference.
  3. The request is saved to Firestore.
  4. The contact profile is updated.
  5. User is redirected to the thank-you page.

What the User Sees

The confirmation messaging tells the user to expect an email from homescopegta@gmail.com and to check junk if they do not see it in the next few hours.

13. Common Troubleshooting

Problem What to Check
Listings missing Admin sync page, DDF credentials, cursor state, visibility filters, scheduler status
Wrong King listings appear Run incremental sync after deploy so Kingston / Kingsville cleanup runs
User says no showing email Lead record, email delivery fields, site recipient settings, junk folder guidance
Featured listings wrong Admin featured page, settings/site featured IDs, listing visibility
Chatbot answer too narrow Current bot is site-content-based, not general AI

Operator Best Practice

Prefer fixing sync logic and rerunning sync instead of manually editing Firestore listing documents. Use Firestore edits only as a last resort.
